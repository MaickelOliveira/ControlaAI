# Dashboard category parity and lighter opening reads

The Dashboard category chart previously summed posted expenses only, while Finanças also included reconciled loan, vehicle, installment and recurring forecasts. Both now use `financePeriodExpenses` and `FinanceCategorySummary`. Category/search/type/account filters and recorded-payment replacement use one shared path. Predictions remain labelled and do not change realized cash balances. The Dashboard loads manual recurring commitments too; a failed recurring read is explicitly reported.

The duplicate warning now opens a native modal with matching date/amount groups, descriptions and source labels. A filtered record includes its counterpart even if a category or bank filter hides it. Matching amount/date is only a clue; records and totals are not changed by reviewing them. Native modal focus/escape behavior and a bounded, wrapping mobile layout keep the review usable.

The historical chart was requesting a full ledger including overview, anchors, authors and accounts. The `view=history` response now contains cent-based posted monthly totals. It still checks current authentication, owner/company access and the bank range limit, reads all bounded report pages, merges loan repayments, applies the normal inclusion/refund rules and fails rather than showing zero when a required source fails. It omits unrelated overview/anchor/account/author reads. The current-period ledger contract and settings Dashboard contract remain available unchanged. The Dashboard bootstrap uses a compact panel view instead of redundantly loading manual finance history and phone links. No completed financial or identity result is cached.

Production inspection on 03/11/2026 found the organization below its current Free-plan egress quota: 0.036 / 5 GB (<1%), with the usage page explicitly stating the quota had not been exceeded. The previous billing cycle displayed 1.649 GB. These figures can lag usage by an hour and do not prove the absence of other latency causes. No billing, compute, RLS, credential or financial-record change was made.

Before publication, the real six-month response contained 797 entries and 1,598,945 JSON characters. The overview alone contained 2,023 sync status rows and 347,428 characters; the historical chart does not need that metadata. Three complete read samples took 2,900 / 2,819 / 1,805 ms including browser-control overhead. Compare the compact response after deployment and verify all monthly totals against the full ledger. Payload figures are application response sizes, not measured Supabase billing reductions or an estimate of database egress.
